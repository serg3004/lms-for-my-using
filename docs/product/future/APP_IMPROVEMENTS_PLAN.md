# План: развитие приложения (голосовой ввод комментариев в чек-листах и следующие доработки) (этап 14)

**Основание:** запрос владельца 2026-11-22: составить новый план работ по всему приложению по образцу прежних; план показан владельцу и отправлен в репозиторий по его команде 2026-11-22. Нумерация продолжает [`USER_ONBOARDING_AND_ACCOUNTS_PLAN.md`](./USER_ONBOARDING_AND_ACCOUNTS_PLAN.md) (последний номер PR 507).
**Статус:** план согласован владельцем 2026-11-22 (все вопросы закрыты, макеты утверждены); выполнен только PR 514 (#1097), остальной код не начат. Каждый PR стартует только по слову «Выполняй PR N». Новые пункты владельца добавляются в конец раздела «Разрывы» и получают следующий номер.
**Цель:** везде, где в приложении можно оставить комментарий, человек может надиктовать его голосом, и текст появляется сам (главное: не печатать); а где нужно, к комментарию прикладывается и сама запись звука. Что из этого включено, настраивают администратор и создатель чек-листа.

## 0. Границы

- **Как есть сейчас (проверено по коду 2026-11-22):** к ответу в чек-листе можно оставить текстовый комментарий (`ChecklistItemResult.comment`, правила `noteRule`, `noteAnswers`, `noteRequired` у пункта), приложить фото (`ChecklistPhoto`, поля `photo*`), у проверяющего есть свой комментарий (`reviewComment`), у сессии есть итоговые поля (`strengths`, `developmentAreas`, `nextSteps`). Загрузка идёт через `upload.service.ts`; для аудио в списке разрешённых только `audio/mpeg` и `audio/wav`, а браузер при записи отдаёт `audio/webm`, `audio/ogg` или `audio/mp4`. Заголовок `Permissions-Policy` на сервере и в nginx запрещает микрофон (`microphone=()`), поэтому запись из браузера сейчас невозможна. Лимит загрузки в nginx 9 МБ, в API 8 МБ.
- **Не входит в этот план:** голосовое управление приложением, звонки и голосовые сообщения между пользователями.
- **Два режима, независимые друг от друга:** (а) **диктовка**: голос превращается в текст прямо в поле комментария, звук нигде не сохраняется; (б) **запись звука**: к комментарию прикладывается аудиофайл, который можно прослушать. Можно включить один режим, оба или ни одного.
- Секреты и персональные данные в репозиторий, логи и документы не попадают; все тексты на RU, EN, KK, ZH; слово «эталон» вместо названия стороннего продукта; бюджет CSS расходуется минимально.
- Диктовка не хранит звук совсем. Запись звука (режим б) это персональные данные: закрытое хранилище, выдача только по правам на сам чек-лист, удаление вместе с сессией.

**Зависимости:** ответ на вопрос 1 ниже.

**Заметки по подготовке (по коду):**

- `Permissions-Policy` сейчас запрещает микрофон (`microphone=()` в API, в nginx; PR 357 оставил так): открыть `microphone=(self)` и поправить `security.audit.spec.ts`.
