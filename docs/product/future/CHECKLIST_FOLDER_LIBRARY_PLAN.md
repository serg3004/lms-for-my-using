**Основание:** замечание владельца 2026-11-02 (скриншоты: текущий экран «Админ → Чек-листы» с деревом папок слева и образец «Учебные материалы» с общим списком папок, кнопкой «+ Создать» и цепочкой пути вверху).
**Статус:** план в `main` (#951), дополнен ответами владельца 2026-11-02 (дерево убирается, колонка «Назначения», контекстное меню на экране и в окне перемещения, «Без баллов» на весь лист, причина по переименованию); открыт вопрос 6 (шкала у новых критериев). **Цель:** папки и листы показываются вместе в одном списке текущей папки, как в образце: сверху цепочка пути, справа кнопка «+ Создать» (папка, чек-лист, из шаблона), строки выбираются по одной или все сразу, папку можно переименовать кнопкой и из контекстного меню по правой кнопке мыши.

## 0. Границы

- Серверная модель папок (PR 395: таблица `checklist_folders`, 5 уровней, защита от циклов и дублей имён, удаление с переводом листов с активными назначениями в черновик, флажок «Видна всем ролям, кроме обучающегося») **не меняется**. Правила прав из PR 395–396 остаются: папкой управляют администратор и создатель, обучающийся папок не видит, цепочка родителей учитывается.
- Меняется экран «Админ → Чек-листы»: вместо левого дерева и общей плоской таблицы «Все листы» появляется один список содержимого открытой папки (папки, затем листы). Новых пунктов меню нет, вкладки «Чек-листы», «Сессии», «Оценочные шкалы» остаются.
- Миграций БД нет (кроме, возможно, индекса, если поиск по всей библиотеке окажется медленным `[НЕ ПРОВЕРЕНО]`). Тексты через i18n RU/EN/KK/ZH. Бюджет CSS (94 KiB) почти исчерпан, новые стили минимальны, цвета инлайном только если без этого нельзя.
- Перетаскивание листов и папок мышью в папки в этот план **не входит** (перемещение остаётся действием «Переместить в папку…»), добавим отдельным PR по просьбе.
- Названия сторонних продуктов в тексты не попадают; образец называется «образец владельца».

## PR 407 — Сервер: данные для библиотеки папок и листов

**Статус:** реализовано в текущем PR; обязательный CI проверяется на его текущем коммите. Экраны PR 408–411 в этот этап не входят.
**Основание:** разрывы 3, 6.
**Цель:** серверу хватает данных для общего списка и действий над смешанным выбором; без этого PR 408–411 пришлось бы собирать из нескольких запросов в браузере.
**Зависимости:** PR 395, PR 396.

**Что необходимо сделать:**
- `GET /checklist-folders`: у каждой папки добавить `creator { id, firstName, lastName }` (как у листа в PR 393; удалённый или безымянный автор отдаётся пустым), счётчики `checklistCount` (прямые листы) и `childFolderCount` (прямые подпапки, только видимые вызывающему);
- `POST /checklists` и создание из шаблона принимают необязательное `folderId`; папка должна быть видна вызывающему и принадлежать организации, иначе 404; без `folderId` лист создаётся в корне, как сейчас;
- массовые действия над папками: `POST /checklist-folders/bulk` с `ids` (до 100) и действием `move { parentId | null }` или `delete`; результат как у `POST /checklists/bulk` (что выполнено, что пропущено и почему: нет права, дубль имени, глубже 5 уровней, перенос в себя или потомка), `delete` возвращает сводку (удалено папок и листов, переведено в черновик); одна запись аудита на операцию; смешанный выбор клиент отправляет двумя запросами (листы и папки), порядок: сначала листы, потом папки;
- поиск по названию: `GET /checklists?search=` ищет по всем папкам организации (с учётом видимости папок), в ответе у листа путь папки, чтобы результат поиска можно было показать с колонкой «Папка»;
- права не расширяются: каждая папка в массовом действии проверяется так же, как при одиночном действии; чужая организация 404;
- документация: `API_CONTRACTS.md`, `API_RBAC_MATRIX.md`, `pnpm docs:generate`.

**Критерии готовности:**
- [x] у папки в ответе есть автор и оба счётчика, счётчик подпапок не раскрывает скрытые папки;
- [x] лист создаётся сразу в выбранной папке, скрытая или чужая папка отклоняется;
- [x] массовый перенос и удаление папок: частичный успех, причины пропусков, проверка 5 уровней и циклов;
- [x] поиск находит листы во всех видимых папках и не показывает листы скрытых;
- [x] тесты на реальной Postgres: изоляция организаций, права, мягкое удаление, аудит;
- Обязательное условие: зелёный CI на текущем коммите PR (актуальный статус — в проверках GitHub).

## PR 410 — Выбор строк (папки и листы) и массовые действия, «Переименовать папку» ✅

**Статус:** выполнен 2026-11-02. Галочки у папок и листов, «выбрать все» берёт строки открытой папки, выбор сбрасывается при переходе и после действия. Панель «Выбрано: N»: только листы как раньше; с папками остаются «Переместить в папку…» и «Удалить», остальные кнопки отключены с подсказкой «Недоступно для папок» и пояснением под панелью; «Переименовать папку» только для одной выбранной папки, которую можно менять (иначе кнопки нет). Перенос и удаление идут двумя запросами (сначала листы, потом папки, `POST /checklist-folders/bulk`), результат сводится в один отчёт с причинами; перенос одной папки из меню строки тоже идёт через этот запрос. Подтверждение удаления считает числа заранее по `delete-impact` верхних выбранных папок плюс выбранные листы. Окно «Переместить в папку…» не предлагает перемещаемые папки и их потомков. Меню строки и кнопка панели открывают одно и то же окно переименования.
**Основание:** разрывы 4, 5.
**Цель:** выбирать галочками и папки, и листы, по одной или все разом; действия над выбором и переименование папки кнопкой.

- вместо «молчаливой» перезагрузки после публикации форма не перезаполняется данными, если в ней есть несохранённые поля (после успешного сохранения это не происходит); при конфликте версий (лист изменён в другом окне) показывается сообщение;
