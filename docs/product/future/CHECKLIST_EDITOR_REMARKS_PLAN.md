# План: доработки редактора листа по замечаниям владельца от 2026-11-04 (этап 8)

**Основание:** замечания владельца при проверке листов 2026-11-04 (скриншоты и описания, присылаются по одному; план дополняется по мере поступления). Замечания добавляются по мере поступления: PR 418–430 по проверке 2026-11-04/05, PR 431–435 по проверке 2026-11-06, PR 436–439 по проверке 2026-11-07.
**Статус:** план составлен и согласован владельцем 2026-11-04, добавлен в `main`. Реализация отдельными PR только по команде «делай» с номером PR. Нумерация PR 418 и далее (407–417 заняты планом папок и библиотеки листов).
**Цель:** редактор листа ведёт себя одинаково во всех своих блоках: то, что можно переставить в «Группах и критериях», можно переставить и в «Общей информации».

## 0. Границы

- PR 436 меняет только расположение блока изображений; PR 437 добавляет одно булево поле листа `showSheetPhotos` (миграция БД, по умолчанию включено); PR 438–439 добавляют выравнивание текста без миграций: оно хранится в самой разметке текста (`text-align` на абзаце, только четыре допустимых значения) и в блоках лонгрида.
- PR 431–435 меняют только расположение и способ редактирования в редакторе листа (вкладки, окно настроек блока, подписи, прокрутка) и исправляют загрузку изображений; хранение оформления и настроек не меняется.
- PR 418–426 меняют только экран редактора листа (`ChecklistBuilder`), предпросмотр, прохождение и результат; PR 427–430 распространяют форматирование текста (PR 420) на остальные поля листа, поля заполнения, другие модули и лонгрид. Новых страниц и пунктов меню нет.
- Серверная модель не меняется: поля «Общей информации» уже хранятся массивом `contextFields` (до 20 штук) с полем `order` у каждого, сервер принимает весь список целиком (`PATCH /checklists/:id`). Миграций БД нет.
- Уже начатые и назначенные сессии не меняются: они держат свой замороженный список полей (`contextFieldsSnapshot`), новый порядок касается только сессий, созданных после сохранения.
- Тексты через i18n RU/EN/KK/ZH. Бюджет CSS (96256 Б, занято 95768 Б) почти исчерпан: стили берём из уже существующих классов строк с перетаскиванием, новых правил минимум.
- Названия сторонних продуктов в тексты не попадают.

## PR 418 — Перестановка везде: «Общая информация» и другие списки редактора (стрелки и перетаскивание) ✅

**Решение владельца 2026-11-04: перестановка нужна везде, где возможно.** Кроме «Общей информации» входят уровни шкалы в настройках листа, пользовательские разделы обратной связи и другие ручные списки редактора без порядка; перечень сверяется по коду при старте PR, для каждого списка те же стрелки, перетаскивание и сохранение порядка, что в «Общей информации».

**Статус:** выполнен (2026-11-04). По коду сверено: порядка не было только у «Общей информации» и у уровней шкалы в настройках листа; у разделов обратной связи, наборов ответов и уровней готовой шкалы стрелки и перетаскивание уже есть. Остаётся проверка владельцем на реальном листе.
**Основание:** разрыв 1.
**Цель:** поля «Общей информации» переставляются так же, как критерии: стрелками «выше / ниже» и перетаскиванием за ручку, порядок сохраняется сразу и виден наблюдателю в том же порядке.
**Зависимости:** нет.

**Заметки по подготовке (по коду):**
- Порядок полей определяет массив и поле `order`: экран наблюдателя и отчёт сортируют по `order` (`sort((a, b) => a.order - b.order)`), редактор рисует в порядке массива. Значит, после перестановки нужно переписать `order` у всех полей подряд (0, 1, 2, …) и сохранить весь список одним запросом, как это уже делают `persistContextFields` и `removeContextField`.
- Поле без названия не отправляется на сервер (`persistContextFields` отбрасывает пустые); при перестановке такого поля порядок сохраняется локально и уйдёт вместе с названием, как сейчас уходит добавление. Поле без названия в списке остаётся и называется «Поле N» (по номеру), пока не получит название; его порядок уходит на сервер вместе с названием.
- Для критериев готовы чистые функции перестановки (`moveItem`, `moveGroup` в `domain.ts`), ручка и контейнер (`DragHandle`, `SortableBox`, `ItemsSortable` в `ChecklistSortable.tsx`) на `@dnd-kit`. Поля «Общей информации» лежат в плоском списке без групп, поэтому отдельный контейнер и функция `moveContextField` проще, чем расширять раскладку критериев (`layout.ts`).

**Что необходимо сделать:**
- чистая функция `moveContextField(fields, fieldId, direction)` и `reorderContextFields(fields, activeId, overId)` в `domain.ts`: возвращают новый список с пересчитанным `order` подряд; граничные случаи (первое поле вверх, последнее вниз, неизвестный id) не меняют список; тесты как у `moveItem`;
- строка поля: слева ручка перетаскивания и стрелки «выше» / «ниже» (первая стрелка скрыта у первого поля, вторая у последнего, как у критериев), метки для экранных дикторов «Переместить поле выше / ниже: {{название}}»; клавиатурная перестановка через ручку, как у критериев (PR 402);
- перетаскивание: поля внутри блока «Общая информация», мышь, касание и клавиатура; перетаскивание поля в «Группы и критерии» невозможно, а критерия в «Общую информацию» тоже;
- сохранение сразу: после перестановки весь список уходит через `persistContextFields`; при ошибке порядок возвращается к прежнему, показывается понятная ошибка рядом с блоком (как «Не удалось сохранить новый порядок. Прежний порядок восстановлен» у критериев PR 402), текст не теряется;

## PR 419 — Критерии: переключатели шкалы не сверху, в колонке «Баллы» видно, откуда баллы ✅
