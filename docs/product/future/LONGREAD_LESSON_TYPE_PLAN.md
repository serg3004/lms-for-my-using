# План развития: Лонгриды — тип урока «лонгрид» (этап 6)

**Основание:** материалы владельца от 2026-10-30: «План пяти приоритетов PDCA v2» (шесть P0-задач LR-P0-01…06 и приложение со старым планом LR-01…LR-18) и HTML-прототип (только образец интерфейса). Решения владельца 2026-10-30: лонгрид входит в MVP; лонгрид — тип урока; существующие задания расширяются до 7 типов.
**Статус:** PR 381–383 выполнены; PR 385 — реализация и проверки в связанном PR; остальные — план. Нумерация продолжает прежние планы: PR 381–392.
**Цель:** автор создаёт в курсе урок типа «лонгрид» (главы, форматированный текст, таблицы, картинки, аудио и видео, 7 типов заданий, кнопки «Продолжить»), публикует его, ученик проходит, результат и прогресс сохраняются на сервере и попадают в существующие отчёты. Это **не новый модуль и не вторая система обучения**: используются `Course`, `Lesson`, `Assessment`, `Progress`, права и загрузки, которые уже есть.

## 0. Границы — обязательно к соблюдению

- Лонгрид — это `Lesson` с `type = 'longread'` (сейчас тип урока — строка со значениями `video`, `text`, `test`, `checklist`, `workplace_check`, `photo`, `practical`). Отдельной библиотеки лонгридов и привязки одного лонгрида к двум курсам нет (пункт LR-01 старого плана про «два контекста» не делаем).
- **Новых пунктов меню нет**: создание и правка идут из существующих экранов уроков и конструктора курса (`AdminLessonsPage`, `AdminCourseBuilderPage`), чтение — из страницы урока ученика (`LearnerLessonDetailPage`).
- Права не расширяются: автор — те, кто уже может править урок курса; читает ученик, которому выдан курс (`CourseAccessPolicy`). Новых ролей нет. Черновик ученику недоступен ни по ссылке, ни по API; чужая организация получает 404.
- Миграции только аддитивные; старые курсы, уроки, материалы, тесты и прогресс работают без изменений. Откат — выключение флага `longreadEnabled`: уроки типа «лонгрид» перестают открываться, остальное работает.
- Хранилище содержимого: типизированная структура (главы и блоки с версией схемы), не HTML из браузера. Безопасная отрисовка по списку разрешённых блоков; произвольный HTML, `iframe` и скрипты запрещены.
- Баллы, правильность ответов, попытки, прогресс и доступ считает **только сервер**; клиент ничего не решает. Правильные ответы не уходят ученику до проверки.
- Тексты через i18n, RU/EN/KK/ZH синхронизированы (`locale-sync.spec.ts`). Бюджет CSS-бандла почти исчерпан: редактор подгружается отдельным чанком, новый CSS — осознанно (измерить до и после).
- Загрузки идут через существующую цепочку (хранилище S3, карантин, сканер, multipart). Сейчас лимит файла 50 МБ; значение 250 МБ из плана — отдельное решение (вопрос 1).
- Каждый PR: Plan (сверка с кодом) → Do → Check (lint, типы, юнит, DB-тесты, e2e, a11y, tenant-тесты) → Act (исправление до зелёного CI). В теле PR: шаги ручной проверки, риск, откат.
- Перед стартом каждого PR сверять с актуальным `main`. Неподтверждённое помечено `[НЕ ПРОВЕРЕНО]`.

## Что выходит за этот план (старый план LR-09, 12, 13, 15, 16, 17 и часть LR-14)

Инфографика, готовые шаблоны блоков, редактор изображений, совместное редактирование в реальном времени, экспорт и перенос между аккаунтами, AI-помощник и перевод, SCORM/xAPI — остаются вне MVP до отдельного решения владельца. Печать и PDF лонгрида и перенос в статью базы знаний (LR-14) — кандидат на этап 7 после приёмки.

## PR 382 — Публикация и неизменяемые версии ✅

**Статус:** ✅ выполнено (PR 382). Пункт про файлы (удаление из черновика не трогает опубликованную версию) переносится в PR 386: файловых блоков до него нет, правило и тест там.

**Заметки по подготовке:** сверить, как сейчас публикуется урок (`LessonStatus`), как `Progress` и `Assessment` ссылаются на урок, и что считать «начатым» прохождением.

**Цель:** ученик читает только опубликованную версию, правки черновика её не меняют, прохождение привязано к версии.

**Зависимости:** PR 381.

**Что необходимо сделать:**
- `LongreadRevision`: неизменяемый снимок документа, глав, блоков, ссылок на файлы, правильных ответов заданий и настроек; номер растёт монотонно, автор и дата;
- публикация, переопубликование и снятие с публикации (`publish`, `republish`, `unpublish`); проверка перед публикацией возвращает перечень причин отказа (пустое обязательное задание, файл не прошёл проверку, битая ссылка, неизвестный блок);
- правило версий: начатые прохождения остаются на своей версии, новые идут на последнюю опубликованную; ответы не переносятся автоматически; снятие с публикации блокирует новые открытия, прежние результаты сохраняются;
- история версий (номер, автор, дата) и «восстановить версию в новый черновик» без изменения исторической версии;
- ученик читает через API только последнюю опубликованную (или свою закреплённую) версию; черновик по идентификатору не отдаётся;
- удаление файла из черновика не удаляет его из опубликованной версии, пока на неё есть ссылки.

**Критерии готовности:**
- [x] публикация v1, правка черновика: ученик видит v1; после v2 новый ученик видит v2, начатое прохождение остаётся на v1;
- [x] восстановление v1 создаёт новый черновик и не меняет v1 и v2;
- [x] черновик и чужая версия недоступны ученику по идентификатору и URL, ошибка без утечки;
- [x] гонка двух публикаций даёт две разные последовательные версии или контролируемый отказ, но не дубль номера;
- [x] тесты на реальной Postgres, документация.

**Риски:** связка версий с существующим `Progress` — решение по миграции данных только аддитивное.

## PR 385 — Ридер ученика и предпросмотр
