## 0. Границы

- **Первая версия сразу охватывает семь областей** (решение владельца 2026-11-18): чек-листы, курсы, лонгриды, тесты, проверки, отчёты, регистрация пользователей.
- **Права только добавляются (union), запретов (`deny`) нет.** Итог пользователя = встроенные роли + все его индивидуальные роли. (Решение владельца 2026-11-18.)
- **Роли создаёт, меняет и назначает только администратор своей организации.** Неделегируемое: управление ролями, выдача системного `admin`, доступ к другой организации, настройки безопасности и удаление организации.
- **Выключатель по организации** на время выкатки; пока выключен, действуют только встроенные политики. Откат возвращает встроенные политики, не удаляя данные.
- **Совместимость:** `rolePolicies` в `apps/api/src/modules/auth/roles.ts` остаются источником прав встроенных ролей; `UserRole` и `Membership.role` не заменяются именами индивидуальных ролей; миграция не выдаёт новых прав текущим пользователям.
- **Права не пишутся в JWT:** проверка по БД на каждый запрос (как сейчас читается `Membership`), отзыв действует со следующего запроса.
- Назначенный наблюдатель сессии остаётся отношением к сессии, а не ролью; право «выбирать наблюдателя» не равно праву читать чужие сессии.
- Слово «эталон» вместо названия стороннего продукта; все новые тексты на RU, EN, KK, ZH; бюджет CSS расходуется минимально.
- Уже есть основа для защитных проверок: `apps/api/src/modules/auth/api-policy.audit.spec.ts`, `roles.guard.spec.ts`, `roles.spec.ts`; около 300 объявлений `@Roles(...)` в контроллерах (чек-листы 113, лонгриды 27, тесты и вопросы 24, курсы и материалы 23, пользователи 8 и др.).
