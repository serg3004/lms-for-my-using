# План работ: визуальный рефреш «Оргструктура» и «Чек-лист-сессии»

**Основание:** прототипы `ORG_STRUCTURE_UI_REFRESH_PROTOTYPE.html` и
`CHECKLIST_SESSIONS_UI_REFRESH_PROTOTYPE.html` (лежат в этой же папке); не зарегистрированы в
CI-enforced `docs/lms-ui-prototypes-complete/manifest.json` — тот же неформальный статус, что был
у `CHECKLIST_WORKPLACE_TRAINING_PROTOTYPE_V3.html` (использовался как "Основание" для полностью
выполненного `CHECKLIST_WORKPLACE_TRAINING_IMPLEMENTATION_PLAN.md` без регистрации в manifest;
теперь архивирован в `docs/archive/old-trackers/` после реализации плана) — это установленная
практика для прототипов, обслуживающих один конкретный product-план, в отличие от manifest'а,
который описывает полный набор экранов приложения.

**Статус:** в работе. PR 309 (аудит оргструктуры) выполнен, его результаты — в разделе «Результат
аудита (оргструктура)» ниже. PR 310 не начат.

**Известные и исправленные ошибки прототипа** (найдены на ревью `serg3004/lms-for-my-using#802`,
коммит `5e647068` и последующий фикс): колонка "Тип" у групп (`Когорта/Команда/Учебная группа`) в
`ORG_STRUCTURE_UI_REFRESH_PROTOTYPE.html` была убрана — `Group` в Prisma-схеме не имеет поля типа,
`AdminGroupsPage.tsx` такую колонку не рендерит; раздел "История импортов" был переписан на реальную
форму `OrgStructureEvent` (дата/тип события/сущность/актор) вместо выдуманного per-файл лога со
статусами "Применён/Требует проверки/Отклонён", которых API не персистит (невалидные превью нигде
не сохраняются); мобильный breakpoint чинил CSS-баг (`.side>div.nav-group` не совпадал с реальной
разметкой `<nav class="nav-group">`, да ещё и inline `style="display:flex"` перебивал правило) —
теперь навигация действительно скрывается на мобильном.

## Важно: чем это НЕ является

Это не план новой функциональности для того, что уже реализовано полностью: дерево подразделений,
должности, требования к обучению по должностям, учебные группы, CSV-импорт с историей; и большая
часть цикла чек-лист-сессий (визард, билдер критериев со шкалами/группами, мобильное проведение с
фото и геолокацией, дашборд руководителя, отчёт с recalculate). Ничего из этого не пересоздаётся и
не переписывается заново.

**Известный функциональный (не layout) пробел, не в scope этого плана:** `ChecklistBuilder`
сохраняет определения `contextFields` листа, но `ChecklistSessionConduct.tsx` их нигде не рендерит
и не собирает — сами значения context-полей во время проведения сессии не захватываются и не
сохраняются. Это открытый функциональный гэп самого чек-лист-модуля (не связан с визуальным
рефрешем), уже отмеченный как таковой в существующем
`CHECKLIST_WORKPLACE_TRAINING_IMPLEMENTATION_PLAN.md`. PR 310 (аудит) не должен закрывать этот
пробел как "визуальное расхождение" — это отдельная, самостоятельная задача бэкенда/UI, вне scope
данного layout-плана.

Прототипы также **не вводят новую палитру**. Первая версия прототипов ошибочно придумывала свой
цвет и бренд — это было замечено владельцем продукта и исправлено на реальные токены проекта:
основной цвет и фон — из настраиваемой org-theme (`apps/web/src/shared/theme.ts`,
`defaultThemeSettings`), статусные цвета (success/warning/danger/info) — из
`apps/web/src/styles/tokens.css`, шрифт — Manrope, как в `apps/web/src/styles/global.css`.
Тёмная тема, которую видно на самих HTML-страницах прототипов, — только оформление для удобства
чтения макета в просмотрщике артефактов; в реальном приложении тёмной темы сейчас нет
(`tokens.css` определяет только один, светлый, набор значений), и этот план её не предполагает.

## Важное исправление после ревью: PR 309 в исходной версии плана был основан на неверной посылке

Первая версия этого плана утверждала, что подтверждённый разрыв с прототипом — это 5 отдельных
пунктов меню оргструктуры вместо одного с вкладками, и описывала это как PR 309. Ревью (Codex) на
`serg3004/lms-for-my-using#802` указало на код, который это опровергает:
`apps/web/src/shared/adminPage.tsx` уже содержит **один** пункт сайдбара «Организационная
структура» (`getAdminNav()`, `ORG_STRUCTURE_TAB_ROUTES`), и все 5 страниц оргструктуры уже рендерят
общий компонент `OrgStructureTabs` — визуальную вкладочную полосу (`.admin-org-tabs`,
подчёркивание акцентным цветом у активной вкладки) поверх пяти разных роутов. Формально это уже
очень близко к тому, что показывает прототип, просто реализовано через полную навигацию браузера
между роутами (`<a href>`), а не через client-side переключение панелей без перезагрузки.

Вывод: заявленный "единственный подтверждённый разрыв" не был на самом деле подтверждён —
сравнение шло по чтению кода отдельных страниц, а не по факту отрисованного UI и не по всему
дереву компонентов (`OrgStructureTabs` был замечен как импорт, но не был прочитан и понят). Это
та же ошибка, которую план изначально пытался не допустить для чек-лист-сессий (PR 310), но не
избежал для оргструктуры. Исправление: PR 309 теперь тоже начинается с аудита, а не с
предполагаемого кода.

## PR 312+ — точечные правки по итогам обоих аудитов

Состав и число этих PR определяются результатами PR 309 и PR 310, а не фиксируются здесь заранее.
Каждая такая PR — один конкретный экран с реальным расхождением, найденным в аудите, не более.
Как и для остальных feature-инициатив репозитория, конкретные PR 312+ по мере открытия дополнительно
заводятся как GitHub Issues/Project work items (`.github/ISSUE_TEMPLATE/work-item.md`) — этот
Markdown-файл фиксирует design-уровень план и историю аудита, а не заменяет собой
`docs/README.md`'s единственного владельца active-work-трекинга.

Номера 312–315 заняты находками PR 309 (оргструктура). Находки PR 310 (чек-лист-сессии) нумеруются с 316.

### PR 312 — «Импорт и история»: локализация экрана

- `AdminOrgStructureToolsPage.tsx`: все строки перевести на `t(...)` с ключами во всех локалях
  (`ru`, `en`, `kk`, `zh`). `brandLabel`, `sidebarLabel` и `navItems` — как на остальных четырёх вкладках.
- Дату выводить в локали пользователя. В «Кто» показывать имя актора (или сокращённый id), а не полный UUID.
- Проверка: скриншот вкладки в `ru-RU`, в тексте нет английских строк.

### PR 313 — таблицы оргструктуры на мобильном

- В `DataTable` на «Должностях», «Требованиях» и «Группах» задать `data-priority` колонкам (как на
  `/admin/users`), чтобы на ≤860px второстепенные колонки уходили в раскрытие строки.
- Общий CSS `DataTable` не трогать. Та же форма поломки есть на `/admin/courses`, но это вне scope плана —
  отдельный work item.
- Проверка: mobile 390, текст в ячейках не переносится по буквам.

### PR 314 — «Подразделения»: переполнение действий

- Ряд действий в карточке выбранного подразделения переносится и не выходит за карточку на desktop 1440.
- Кнопки в шапке страницы на mobile 390 не обрезаются краем экрана.

### PR 315 — общая шапка оргструктуры

- Один заголовок «Организационная структура» с описанием, под ним `OrgStructureTabs`. Единый eyebrow.
  Счётчики на вкладках — только если число уже есть в данных страницы, без новых API-запросов.
- На mobile вкладки идут в одну строку с горизонтальным скроллом, а не переносятся.
- Пояснение «Группа — учебная когорта, не подразделение» на вкладке «Группы».
