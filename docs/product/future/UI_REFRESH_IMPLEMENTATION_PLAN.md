# План работ: визуальный рефреш «Оргструктура» и «Чек-лист-сессии»

**Основание:** прототипы `ORG_STRUCTURE_UI_REFRESH_PROTOTYPE.html` и
`CHECKLIST_SESSIONS_UI_REFRESH_PROTOTYPE.html` (лежат в этой же папке).

**Статус:** не начато. Ни один PR из этого плана ещё не открыт.

## Важно: чем это НЕ является

Это не план новой функциональности. Аудит перед составлением плана (ручная проверка кода
`apps/web/src/app/AdminDepartmentsPage.tsx`, `AdminPositionsPage.tsx`, `AdminPositionCoursesPage.tsx`,
`AdminGroupsPage.tsx`, `AdminOrgStructureToolsPage.tsx`, `AdminChecklistSessionsPage.tsx`,
`ChecklistSessionWizard.tsx`, `admin-checklists/ChecklistBuilder.tsx`, `ChecklistSessionConduct.tsx`,
`ManagerChecklistsPage.tsx`, `AdminChecklistSessionReportPage.tsx`, Prisma-схемы) подтвердил: **вся
функциональность обоих разделов уже реализована** — дерево подразделений, должности, требования к
обучению по должностям, учебные группы, CSV-импорт с историей; и полный цикл чек-лист-сессий
(визард, билдер критериев со шкалами/группами/context-полями, мобильное проведение с фото и
геолокацией, дашборд руководителя с donut- и line-графиками, отчёт с recalculate). Ничего из этого
не пересоздаётся и не переписывается заново.

Прототипы также **не вводят новую палитру/шрифты**. Первая версия прототипов ошибочно придумывала
свой цвет и бренд — это было замечено владельцем продукта и исправлено: обе HTML-страницы в этой
папке используют ровно те токены, что уже есть в `apps/web/src/shared/theme.ts`
(`defaultThemeSettings`: `colorPrimary: '#4f46e5'`, `adminSidebarBackground: '#111827'` и т.д.) —
то есть тот же брендинг, что организация уже может настраивать через существующую страницу
«Оформление» (`AdminThemeSettingsPage.tsx`). Задача этого плана — **только layout/IA** (расположение
экранов, состав вкладок, визуальная плотность существующих таблиц/карточек), не дизайн-система.

## Известный, подтверждённый разрыв

- **Оргструктура**: сейчас 5 отдельных страниц/роутов (`/admin/departments`,
  `/admin/positions`, `/admin/position-courses`, `/admin/groups`, `/admin/org-structure-tools`)
  вместо одной страницы с вкладками, как в прототипе. Это единственный подтверждённый layout-разрыв.
- **Чек-лист-сессии**: разрыв с прототипом **не подтверждён на реальном рендере** — сравнение в
  этой сессии шло по коду (JSX/классы), а не по факту отрисованных экранов в браузере. Не
  предполагать объём работ здесь заранее — см. PR 310 ниже, которая существует именно чтобы
  установить факт, а не гипотезу.

## PR 309 — Оргструктура: объединение 5 страниц в одну вкладочную настройку

**Цель:** `/admin/org-structure` с вкладками «Подразделения / Должности / Требования / Группы /
Импорт и история» вместо пяти отдельных пунктов меню, без изменения данных/API/RBAC.

**Изменения:**
- Новый роут-контейнер с табами (переиспользует существующие `OrgStructureTabs`/`AdminPageLayout` из
  `apps/web/src/shared/adminPage.tsx`), рендерящий существующие страничные компоненты как вкладки
  вместо самостоятельных страниц.
- Старые роуты (`/admin/departments`, `/admin/positions`, `/admin/position-courses`,
  `/admin/groups`, `/admin/org-structure-tools`) остаются как redirect на соответствующую вкладку
  нового роута — не ломать существующие закладки/ссылки в уведомлениях.
- Пункт меню в сайдбаре: один пункт «Организационная структура» вместо пяти.
- Без изменений в `apps/api` — чисто фронтенд-роутинг.

**Критерии готовности:**
- [ ] `/admin/org-structure` существует, все 5 вкладок рендерят прежний функционал без регрессий;
- [ ] старые 5 роутов редиректят на новую страницу с сохранением текущей вкладки/состояния фильтров, где это применимо;
- [ ] сайдбар показывает один пункт вместо пяти;
- [ ] существующие E2E/accessibility тесты для всех пяти страниц зелёные под новыми роутами (обновлены, не удалены);
- [ ] visual regression обновлён осознанно (не bulk-approve).

## PR 310 — Чек-лист-сессии: визуальный parity-аудит (устанавливает факты, не гипотезы)

**Цель:** получить реальный, подтверждённый список расхождений между прототипом и текущими экранами
чек-лист-сессий, вместо предположений. Эта PR **не меняет код** — только производит доказательную
базу для follow-up PR.

**Изменения:**
- Запустить dev-сервер (`/run` или эквивалент), пройти все 7 экранов реальными действиями
  (admin sessions list, wizard, builder, instructor conduct, learner sessions, manager dashboard,
  session report) под тестовым пользователем каждой роли.
- Сделать скриншоты каждого реального экрана.
- Сравнить каждый экран построчно с соответствующим состоянием `CHECKLIST_SESSIONS_UI_REFRESH_PROTOTYPE.html`.
- Результат — таблица в этом же файле плана (раздел «Результат аудита» ниже), с колонками:
  экран | реальный вид сейчас | расхождение с прототипом | оценка объёма (нет / мелкая правка /
  отдельная PR).
- Только пункты с реальным расхождением попадают в план как новые PR (311+); пункты без
  расхождения закрываются без изменений кода.

**Критерии готовности:**
