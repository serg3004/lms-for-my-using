# План развития: Чек-лист — обучение на рабочем месте (этап 2)

**Основание:** `docs/product/future/CHECKLIST_WORKPLACE_TRAINING_IMPLEMENTATION_PLAN.md` (PR 285–308, реализован), `docs/product/future/UI_REFRESH_IMPLEMENTATION_PLAN.md` (PR 309–323, реализован), анализ разрывов `CHECKLIST_GAP_ANALYSIS.md` и просмотр живого интерфейса по ролям (admin / manager / learner / instructor на мобильном).
**Статус:** реализация идёт: PR 324–334 выполнены (✅ в заголовке, критерии отмечены), далее PR 335. Нумерация продолжается с **PR 324** (последний занятый номер в репозитории — PR 323). Диапазон PR 324–341: PR 338–341 добавлены после разбора экрана создания чек-листа и идут отдельной веткой.
**Цель:** это **не новый модуль**. Это доработка существующего режима «сессия наблюдения» (`apps/api/src/modules/checklists/`, frontend `AdminChecklistSessionsPage`, `ChecklistSessionConduct`, `ManagerChecklistsPage` и др.): исправить найденный баг, упростить основные сценарии для обычного пользователя и закрыть функциональные разрывы.

## 0. Границы — обязательно к соблюдению

- Контракты первого плана (разделы 0 и 0.1) действуют без изменений: никакого нового module boundary, семейство `Checklist*`, `ChecklistSession` — overlay 1:1 над `ChecklistInstance`, Observer = роль `instructor`, новых ролей нет.
- **Новых пунктов меню нет.** Единственный новый nav-item модуля (`/manager/checklists`) уже существует; всё остальное — вкладки, диалоги, под-маршруты.
- Миграции только аддитивные. Новые поля попадают в `templateSnapshot` на момент назначения, существующие snapshot не меняются.
- RBAC на сервере, фронтенд не источник истины. Новые policies — в `roles.ts`, без дублирования.
- Дизайн не копируется с других продуктов: переиспользуется дизайн-система LMS (`Badge`, `Dialog`, `DataTable`, `AdminPageLayout`).
- Перед стартом каждого PR сверять с актуальным main: часть пунктов могла быть закрыта параллельными PR.

# Definition of Done

Этап 2 считается завершённым, только если:

- [ ] нет невидимого текста и других критичных UI-багов на экранах проведения (mobile);
- [ ] список сессий фильтруется по листу, подразделению, сотруднику и открывает отчёт по клику;
- [ ] мастер создания позволяет задать индивидуальное время и продолжительность;
- [ ] есть настройки листа `allowFinishIncomplete` и `forbidGalleryPhotos`;
- [ ] наблюдатель может создать сессию для себя и видит прошлые сессии перед стартом;
- [ ] не начатую сессию можно редактировать и удалять, участнику можно написать;
- [ ] дашборд руководителя показывает подразделения, поиск, сортировку и быстрые действия;
- [ ] пересчёт поддерживает выбор формулы с неизменяемой историей;
- [ ] чек-лист не создаётся в БД до первого сохранения, причины недоступности публикации видны;
- [ ] конструктор: один способ добавить критерий, настройки разделены на «Оценка» и «Дополнительно», видно состояние сохранения;
- [ ] можно создать лист из шаблона или копированием;
- [ ] есть CSV-экспорт с учётом scope и аудитом;
- [ ] напоминания и email подтверждены на живом production (или явно `[НЕ ПРОВЕРЕНО]` с решением владельца);
- [ ] существующие Checklist flows (unit/integration/E2E) не регрессировали, обязательный CI зелёный;
- [ ] accessibility и visual regression проходят на изменённых экранах;
- [ ] новых top-level пунктов меню не появилось.
