# План развития: Чек-лист — права и роли по таблице владельца (этап 4)

**Основание:** таблица прав владельца `CHECKLIST_ROLE_PERMISSIONS_TABLE.md` (22 строки × 5 ролей: администратор, руководитель, инструктор / наблюдатель, наставник, сотрудник; присланная 2026-10-27), сверка с `main` после PR 358 — `apps/api/src/modules/auth/roles.ts` (`rolePolicies`), `ChecklistsController`, `ChecklistReviewAccessService`, `checklist-session.service.ts`, `docs/contracts/API_RBAC_MATRIX.md`, `docs/product/future/CHECKLIST_WORKPLACE_TRAINING_PARITY_PLAN.md` (PR 343–358) и `docs/product/future/CUSTOM_ROLE_PERMISSIONS_PLAN.md`.
**Статус:** план, реализация не начата. Нумерация продолжается с **PR 359** (последний занятый номер плана паритета — PR 358). Диапазон PR 359–367.
**Цель:** это **не новый модуль**. Привести фиксированные роли и права модуля «Чек-листы» к таблице владельца: таблица становится эталоном, код и тесты сверяются с ней автоматически.

## 0. Границы — обязательно к соблюдению

- Контракты первого плана (разделы 0 и 0.1 `CHECKLIST_WORKPLACE_TRAINING_IMPLEMENTATION_PLAN.md`), плана этапа 2 и плана паритета (раздел 0) действуют без изменений: никакого нового module boundary, семейство `Checklist*`, `ChecklistSession` — overlay 1:1 над `ChecklistInstance`.
- **Новых пунктов меню нет.** Всё — существующие экраны, диалоги и вкладки.
- Роли остаются фиксированными (`admin`, `manager`, `instructor`, `mentor`, `learner`); настраиваемые наборы прав — отдельный план `CUSTOM_ROLE_PERMISSIONS_PLAN.md` (`DEC-CHKS-004`), в эти PR не входят.
- RBAC на сервере, фронтенд не источник истины. Новые и изменённые policies — только в `roles.ts`, затем синхронизировать `docs/contracts/API_RBAC_MATRIX.md`. Расширение прав роли всегда сопровождается cross-tenant тестом и тестом на запрет для ролей, которым право не выдано.
- Зона видимости («вся организация» / «своя команда» / «только свои») определяется только серверными scope-функциями (`sessionScope()`, `observerActionScope()`, `participantLearnerScope()`, `reviewQueueScope()`); клиентских фильтров вместо них нет.
- Миграции только аддитивные. Существующие записи не меняют смысл: права расширяются, а не отзываются; если строка таблицы **сужает** текущее право, это отмечается отдельным решением владельца.
- Все пользовательские тексты через i18n, RU/EN/KK/ZH синхронизированы (`locale-sync.spec.ts`, `checklist-module-keys.spec.ts`). Бюджет CSS-бандла почти исчерпан: новый CSS требует осознанного повышения.
- Перед стартом каждого PR сверять с актуальным `main` и с планом паритета: PR 351–355 (наблюдатели, свободное прохождение, закрепление) и PR 356 (отчёт по руководителям) пересекаются с этим планом по строкам «свободное прохождение» и «своя команда».
- Неподтверждённое помечается `[НЕ ПРОВЕРЕНО]`.

6. **Просмотр заполненного свободного листа (PR 366).** Принято по умолчанию 2026-10-29: сотрудник видит свой результат, остальные роли — в своей зоне видимости. Открыто для исправления.
