# Матрица приёмки модуля «Тесты» (PR 536)

Требования описаны в [плане модуля «Тесты»](ASSESSMENTS_MODULE_PLAN.md). Существующие проверки указаны по состоянию на `d377c959`. Их наличие не подтверждает прохождение приёмки. Полный прогон зависит от PR 537–544 и PR 571.

| Разрыв | Существующая проверка | Что проверить при приёмке |
|---|---|---|
| 99 | [Папки в браузере][folders], [операции с папками в PostgreSQL][folders-db] | Перенос теста в папку и появление в библиотеке со счётчиком. |
| 100 | [Фильтры, сортировка и страницы в браузере][library] | Сохранение выбранного фильтра при работе с тестом и возврате в библиотеку. |
| 101 | [Создание, порядок, предпросмотр и публикация][editor] | Копирование, несохранённые правки и вкладка «Где используется». |
| 102 | [Завершение по таймеру][types] | Задать лимит в редакторе и проверить сообщение сотруднику. |
| 103 | [Прохождение семи типов][types] | Создать и отредактировать типизированные вопросы через интерфейс автора. |
| 104 | | Проверить границы окна доступности, паузу, зачёт попытки, режимы разбора и показ по одному вопросу. |
| 105 | [Предупреждение о правке вопроса по ссылке][bank] | Подключить вопрос из папки банка, импортировать и проверить выборку N вопросов. |
| 106 | [Возобновление с сохранёнными ответами][types] | Навигация, отметка «вернуться» и разбор на телефоне. |
| 107 | [Расчёт аналитики с ограничением по месту размещения][results] | Сверить распределение, сложность, ответы, подразделения и динамику по завершённым попыткам. |
| 108 | [Очередь выгрузки и права на файл][exports], [формирование PDF][pdf] | Открыть XLSX и PDF по тесту и по папке, сверить фильтры и анализ вопросов. |
| 109 | [Повторное открытие сохранённого вопроса и ключа][results] | Изменить опубликованный тест и сверить старую попытку, журнал и результаты после миграции. |
| 110 | | Опубликовать самостоятельный тест и проверить тот же тест в курсе и лонгриде. |
| 111 | [Назначение самостоятельного теста и прохождение по ссылке][standalone] | Проверить назначения сотруднику, группе и подразделению, срок, «Мои тесты» и результат без курса. |
| 112 | | Проверить очередь, выставление балла, комментарий и уведомление сотруднику. |
| 113 | Ожидает PR 537 | Проверить материалы у вопроса, варианта ответа и описания на телефоне, в предпросмотре и разборе. |
| 114 | Ожидает PR 538 | Проверить титульный экран и все три варианта завершения. |
| 115 | Ожидает PR 538 | Проверить тему организации и переопределение акцента и шрифта тестом. |
| 116 | Ожидает PR 539 | Пройти оба новых типа, сопоставление с дистракторами и смену режима выбора. |
| 117 | Ожидает PR 540 | Пройти опрос со шкалой Ликерта и сверить отчёт по ответам. |
| 118 | Ожидает PR 541 | Применить инструменты редактора изображений и открыть результат после сохранения. |
| 119 | Ожидает PR 542 | Открыть редактор двумя авторами, проверить права соавтора и защиту от перезаписи. |
| 120 | Ожидает PR 543 | Проверить формат описания, события результата и сопоставление полей SCORM и xAPI. |
| 121 | Ожидает PR 544 | Создать шаблон анкеты, назначить тесту, отправить ответ и отключить анкету. |
| 145 | Ожидает PR 571 | Сверить экран и PDF попытки, оба режима подсчёта баллов и доступ администратора и создателя. |

Сквозной сценарий связывает папку, один тест во всех трёх местах размещения, все типы вопросов, прохождение, ручную проверку, аналитику и выгрузку. Проверка доступа должна включать успешные действия разрешённых ролей и отказ для пользователя другой организации при обращении к тем же данным. Контракты API описаны в [API_CONTRACTS.md](../../contracts/API_CONTRACTS.md).
