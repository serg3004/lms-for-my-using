## PR 575 — Одно окно папки: цвет и доступ в тестах и чек-листах ✅

**Статус:** выполнен вместе с PR 576 ([#1155](https://github.com/serg3004/lms-for-my-using/pull/1155), запрос владельца 2026-11-27). Цвет и пункт «Настроить папку» были сделаны раньше (PR 515); здесь общее окно получило блок доступа во всех разделах: тесты, чек-листы, курсы, задания, материалы. e2e и снимки отдельно не добавлялись.
**Основание:** PR 395, 409, 525, 574; разрыв: окна папок в тестах и чек-листах различаются.
**Цель:** создание и настройка папки выглядят и работают одинаково, цвет задаётся и меняется везде.
**Зависимости:** PR 574 (слит).

**Что необходимо сделать:**
- Общее окно `FolderDialog` всегда показывает три блока: «Название», «Цвет папки», «Кто видит» (блок доступа берётся из PR 576; до него остаётся старый флажок только в чек-листах).
- Папки чек-листов получают поле `color` (по умолчанию фиолетовый, как у тестов), миграция без потери данных; API создания и изменения принимает цвет; значок в дереве, списке и крошках берёт цвет.
- Пункт «⋮» у папки чек-листа называется «Настроить папку», как в тестах, и открывает то же окно.
- Тексты на четырёх языках (RU, EN, KK, ZH).

**Критерии готовности:**
- [x] окна создания папки в тестах и чек-листах состоят из одинаковых блоков
- [x] цвет папки чек-листа выбирается при создании и меняется позже
- [x] миграция не меняет существующие папки (цвет по умолчанию)
- [x] тесты API и интерфейса (e2e и снимки не добавлялись)

## PR 576 — Доступ к папкам: все сотрудники или выбранные роли ✅

**Статус:** выполнен ([#1155](https://github.com/serg3004/lms-for-my-using/pull/1155), запрос владельца 2026-11-27). Отличия от первой формулировки: вместо трёх переключателей в окне остался флажок «Видна всем ролям, кроме обучающегося» и под ним, если флажок снят, флажки ролей (руководитель, преподаватель, наставник); пусто означает «только создатель и администраторы». Вариант «включая обучающихся» не делался: обучающийся папок не видит. Дополнительно, по замечанию владельца, везде есть «Открыть сотрудникам по имени». Папки курсов, заданий и материалов получили те же поля; у существующих папок видимость сохранена (чек-листы: ранее открытые остались открытыми; папки тестов открыты всем сотрудникам, поэтому старые тесты видны как раньше; папки курсов, заданий, материалов тоже). В списке метка замка с ролями есть только у чек-листов. Сейчас папки курсов и материалов видит и меняет только администратор, поэтому доступ для других ролей там начнёт действовать, когда им откроют эти разделы; сами курсы и материалы из закрытой папки в общем списке по-прежнему показываются.
**Основание:** запрос владельца 2026-11-24: открывать папку любому зарегистрированному сотруднику или отдельной роли; в тестах доступа к папке нет.
**Цель:** у папки тестов и чек-листов один понятный выбор «кто видит».
**Зависимости:** PR 575.

**Что необходимо сделать:**
- Вместо флажка `visibleToStaff` — выбор из трёх: «Только я и администраторы» (по умолчанию), «Все сотрудники» (включая обучающихся) и «Выбранные роли» (список ролей с флажками).
- Данные: режим доступа и список ролей у папки; миграция переносит `visibleToStaff = true` в «Выбранные роли: все, кроме обучающегося», `false` в «Только я и администраторы»; то же поле добавляется папкам тестов (сейчас всё видно по правам на тесты).
- Сервер проверяет доступ при показе папки, её содержимого, поиске и прямой ссылке: вложенное видно, только если видны все папки выше; создатель и администраторы видят всегда; чужая закрытая папка отвечает «не найдено», а не «нет прав».
- Окно папки (PR 575) показывает выбор доступа и краткую подсказку под каждым вариантом; в списке у папки метка «Всем» или «Роли: …» рядом с названием.
- Тексты на четырёх языках; запись в журнал аудита при смене доступа.

**Критерии готовности:**
- [x] папку можно открыть всем сотрудникам, одной роли или нескольким ролям, в тестах и чек-листах
- [x] обучающийся папок не видит (решение: вариант «включая обучающихся» не делался)
- [x] старые папки сохраняют текущую видимость после миграции
- [x] проверка на сервере: прямая ссылка и поиск не обходят доступ
- [x] тесты API (роли, имена, вложенные папки) и интерфейса (e2e и снимки не добавлялись)

## PR 577 — Переключатель темы: подписанное меню вместо трёх значков по кругу

**Статус:** план.
**Основание:** фото владельца 2026-11-24 («телевизор, солнце, луна»); PR 573.
**Цель:** пользователь сразу понимает, какие бывают темы и какая выбрана.
**Зависимости:** PR 573 (слит).

**Что есть сейчас:** одна кнопка листает три режима по кругу: «как в системе» (монитор, по умолчанию), «светлая» (солнце), «тёмная» (луна). - В режиме «Как на устройстве» подсказка пишет, какая тема сейчас применена («сейчас светлая»).
- Новые темы (PR 578) добавляются в это же меню новым пунктом.
- Тексты на четырёх языках; меню работает с клавиатуры и экранных читалок как остальные меню шапки.

**Критерии готовности:**
- [ ] режимы выбираются из подписанного меню, текущий отмечен
- [ ] режим «Как на устройстве» показывает, какая тема применена

## PR 579 — Редактор оценочной шкалы: уровни в ровную строку, один выбор цвета, одна навигация

**Статус:** план.
**Основание:** фото владельца 2026-11-24 («Шкалы»); PR 343, 369б (цвета уровней), 566–569 (правила вида).
**Цель:** шкала редактируется без путаницы: ряды одинаковой высоты, цвет выбирается одним понятным элементом, наверху одна навигация.

**Что есть сейчас (по фото и коду `HighlightColorField`, `ScaleEditor`):**
- Цвет уровня занимает целый узел из четырёх частей: цветной квадрат-палитра, второй такой же квадрат (системный выбор цвета), поле с кодом `#C62828` и шесть быстрых цветов, которые при открытии раскрываются под полем. Два одинаковых квадрата выглядят дублем.
- Открытая палитра делает один ряд выше другого, поля названий получаются разной ширины, а квадраты «висят» над полем кода.
- Порядок уровней меняется только кнопками «вверх» и «вниз», перетащить уровень мышью нельзя (в критериях листа перетаскивание есть, PR 403).
- Над страницей три уровня навигации подряд: вкладки «Чек-листы, Сессии, Оценочные шкалы, Аналитика», вторые вкладки «Оценочные шкалы, Наборы ответов» и хлебные крошки «Чек-листы / Оценочные шкалы / Новая шкала»; крошки повторяют вкладки.
- У строк уровней нет подписей столбцов («Название», «Баллы», «Цвет»); у названия шкалы нет подсказки, что это; блок «Предпросмотр» мелкий и далеко от уровней.

**Что необходимо сделать:**
- Единый компонент выбора цвета `ColorField` на всё приложение, на основе существующего `HighlightColorField`: ряд квадратных образцов (шесть быстрых цветов, как сейчас), «Свой цвет» (системный выбор любого цвета) и поле кода `#RRGGBB`; выбранный образец обведён. Один образец, а не два одинаковых. Цвет уровня стоит второй строкой под названием и баллами, поэтому все уровни одной высоты и ничего не раскрывается.
- Тот же `ColorField` ставится везде, где выбирается цвет: уровни шкалы, цвета результата в настройках модуля и рабочего места, цвета папок (с шестью фирменными цветами папок и «Свой цвет»); отдельных вариантов выбора цвета больше нет.
- Ряды уровней одной сетки: «Название» (растягивается), «Баллы» (узко), «Цвет», кнопки «вверх, вниз, удалить»; сверху подписи столбцов; на телефоне уровень становится карточкой из двух строк.
- Перетаскивание уровня мышью и пальцем за ручку слева (тот же механизм, что у критериев в PR 403); кнопки «вверх» и «вниз» остаются для клавиатуры; порядок обновляется сразу, подсказка где отпустить.
- Убрать хлебные крошки там, где есть вкладки; вместо них одна кнопка «← К шкалам»; заголовок страницы получает короткую строку-подсказку.
- Предпросмотр шкалы показывается справа от уровней (на телефоне под ними) цветными плашками с названием и баллами, как в сессии.
- Тексты на четырёх языках; снимки обновлены.

**Критерии готовности:**
- [ ] все уровни одной высоты, открытие выбора цвета не сдвигает строки
- [ ] один общий компонент выбора цвета с быстрыми цветами, «Свой цвет» и кодом; используется в шкалах, настройках и папках
- [ ] над редактором одна навигация, есть кнопка «← К шкалам»
- [ ] уровни перетаскиваются мышью и пальцем, кнопки вверх и вниз работают с клавиатуры
- [ ] у столбцов есть подписи, на телефоне (320–375 px) строки не ломаются
- [ ] предпросмотр рядом с уровнями
- [ ] тесты интерфейса и доступности, e2e (`checklist-scale-editor`), снимки обновлены

## Как объединить в меньшее число PR

Один PR на всё не рекомендую: в нём миграция базы (цвет и доступ папок), права на сервере и пять экранов, ревью и откат такого PR тяжёлые, а один сбой снимков или теста держит всё. Три PR по смыслу:

| Новый PR | Что входит | Почему вместе |
|---|---|---|
| **A: Папки** | 575 + 576 + общий `ColorField` (цвета папок) | одно окно, одна миграция, один набор проверок доступа |
| **B: Шкалы** | 579 + 517 (карточки, архив, фильтр) + перетаскивание уровней | один раздел «Оценочные шкалы», `ColorField` из A |
| **C: Тема** | 577 + 578 | одни и те же файлы переключателя и переменные цвета |

Порядок: A, затем B (использует `ColorField`), C независим. Добавляются к уже запланированным 515 (вид папок), 516 (сессии), 518–521 (аналитика); 515 удобно сделать вместе с A.
