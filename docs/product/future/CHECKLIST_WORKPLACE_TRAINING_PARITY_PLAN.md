## PR 343 — Редактор уровней оценочной шкалы

**Статус:** план.

**Цель:** администратор создаёт и правит шкалу целиком: название, уровни, баллы.

**Зависимости:** PR 293, PR 342.

**Что необходимо сделать:**
- в окне шкал (`ScaleManagerDialog`) добавить редактирование: добавить и удалить уровень, изменить название и баллы уровня, порядок уровней;
- использовать существующий `PATCH` шкалы с полной заменой уровней (`ChecklistScaleService.update`), новых эндпоинтов не нужно;
- при создании шкалы пользователь сразу видит и правит уровни, а не получает набор по умолчанию;
- предупреждение: изменение действует на новые и ещё не начатые сессии; начатые сессии держат снимок;
- валидация: минимум два уровня, баллы целые, названия непустые и уникальные.

**Критерии готовности:**
- [ ] шкалу можно создать и отредактировать с произвольным числом уровней и баллов;
- [ ] снимки существующих назначений не меняются (тест на реальном Postgres);
- [ ] аудит `checklist_scale.updated`, RBAC `checklistsCreate`, без новых ролей;
- [ ] RU/EN/KK/ZH, unit, accessibility, visual baseline окна шкал.

## PR 344 — Шкала по умолчанию

**Статус:** план.

**Цель:** у организации есть защищённая шкала «Да/Нет», которую нельзя изменить, и она подставляется по умолчанию.

**Зависимости:** PR 343.

**Что необходимо сделать:**
- аддитивное поле `ChecklistScale.isDefault` (по умолчанию `false`) и создание шкалы «Да/Нет» для организации при первом обращении (идемпотентно);
- шкала по умолчанию помечена замочком, редактирование, архив и удаление отвечают 400/409 с понятным текстом;
- в конструкторе новая шкала критерия по умолчанию — эта шкала.

**Критерии готовности:**
- [ ] шкала по умолчанию создаётся один раз на организацию (тест на повторный вызов и конкурентность);
- [ ] изменить, архивировать и удалить её нельзя ни из UI, ни через API;
- [ ] существующие листы не меняются, миграция аддитивная и обратимая.

## PR 345 — Уведомления об изменениях сессии

**Статус:** план.

**Цель:** участники узнают о создании, переносе и удалении сессии, сотрудник — о завершении, админы — о блокировке наблюдателя.

**Зависимости:** PR 333, PR 337 (почта — по готовности).

**Что необходимо сделать:**
- при создании, изменении времени или наблюдателя и удалении сессии создавать `Notification` для сотрудника и наблюдателя по схеме PR 333 (`Notification` + `OutboxEvent`, email best-effort);
- при завершении сессии уведомлять сотрудника (без текста обратной связи и геопозиции в письме, только ссылка);
- при блокировке или удалении пользователя-наблюдателя, у которого есть не начатые или не завершённые сессии, уведомлять администраторов (список сессий в ссылке);
- не уведомлять повторно при идемпотентном повторе запроса; уважать подавление напоминаний у удалённых сессий.

**Критерии готовности:**
- [ ] каждое событие создаёт ровно одно уведомление на получателя (тесты на повтор и конкурентность);
- [ ] письма не содержат обратной связи, геопозиции и e-mail других людей;
- [ ] изоляция организаций и зоны руководителя проверены (IDOR);
- [ ] RU/EN/KK/ZH, документация по уведомлениям обновлена.

## PR 346 — Проведение сессии: навигация и «Скрыть отвеченное»

**Статус:** план.

**Цель:** наблюдатель быстро находит пропущенные вопросы и перемещается по листу.

**Зависимости:** PR 330, PR 332.

**Что необходимо сделать:**
- в `ChecklistSessionConduct` добавить оглавление листа (группы со счётчиком отвеченных) и переход к группе;
- переключатель «Скрыть отвеченное» показывает только неотвеченные критерии;
- перед «Завершить» показать, сколько критериев осталось, с переходом к первому;
- сохранить текущий пошаговый ввод и автосохранение без изменений.

**Критерии готовности:**
- [ ] навигация работает на 320–768 px, клавиатурой и экранным диктором (accessibility);
- [ ] состояние переключателя не теряется при паузе и возобновлении;
- [ ] visual baseline экрана проведения обновлён и просмотрен.

## PR 347 — Права: сверка матрицы и настраиваемая роль (после решения владельца)

**Статус:** план, начинается с решения владельца.

**Зависимости:** решение владельца по `DEC-CHKS-004` (нужна ли настраиваемая роль).

- если «нужна»: отдельный план (новая модель ролей затрагивает всё приложение и не входит в этот PR).

**Критерии готовности:**
