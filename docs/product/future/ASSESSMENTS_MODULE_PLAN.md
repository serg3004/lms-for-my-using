# План: модуль «Тесты» (папки как в чек-листах, редактор, вопросы, настройки, прохождение, аналитика и отчёты) (этап 15)

**Основание:** запрос владельца 2026-11-22: проверить модуль «Тесты», предложить улучшения (визуально, функционально, аналитика, отчёты и так далее) и обязательно дать возможность создавать папки, как в чек-листах. Нумерация продолжает [`APP_IMPROVEMENTS_PLAN.md`](./APP_IMPROVEMENTS_PLAN.md) (последний номер PR 521).
**Статус:** план согласован владельцем 2026-11-22/23 (все вопросы закрыты, макет показан и принят; 2026-11-23 добавлен PR 571 «отчёт по попытке сотрудника»); код не начат. Каждый PR стартует только по слову «Выполняй PR N». Новые пункты владельца добавляются в конец раздела «Разрывы» (после PR 571 — с номера 572).
**Цель:** тест становится самостоятельным модулем (его можно использовать сам по себе, в курсе и в лонгриде), им удобно управлять, когда их сто и больше (папки, поиск, фильтры), тест собирается в понятном редакторе со всеми типами вопросов и нужными настройками, сотрудник проходит его без потери ответов, а у администратора есть настраиваемая аналитика и выгрузки по тесту, вопросам, подразделениям и сотрудникам.

## 0. Границы

- **Как есть сейчас (проверено по коду 2026-11-22):** страница `/admin/assessments` («Конструктор тестов») показывает плоскую таблицу тестов с поиском и фильтром по статусу. Тест (`Assessment`) обязательно привязан к курсу (`courseId`) и по желанию к уроку (`lessonId`); папок нет. Настройки: проходной балл, число попыток, доступность после прохождения курса, показ правильных ответов, перемешивание, сообщения о результате, описание. В модели есть `timeLimitMinutes`, и страница прохождения таймер умеет, но в форме администратора поля «лимит времени» нет. Вопросы и варианты правятся в модальном окне 720 px: у вопроса отдельные кнопки, перетаскивания нет. В базе семь типов вопросов (`single_choice`, `multiple_choice`, `true_false`, `matching`, `ordering`, `fill_blank`, `short_answer`), но в этом редакторе правятся только варианты с выбором, для остальных показывается «тип недоступен» (`typedQuestionUnavailable`); их создают упражнения лонгрида. Число вопросов и попыток в списке считается отдельными запросами на каждый тест (два запроса на строку).
- **Отчёты сейчас:** на тест есть список попыток, результаты и сводка (`/assessments/:id/report`): число попыток, сдали, не сдали, средний, наибольший и наименьший процент, разрез по версиям лонгрида. Анализа по вопросам, распределения баллов, разреза по подразделениям и динамики нет.
- **Общая основа:** тесты и вопросы лонгрида живут в тех же таблицах (`Assessment` с `lessonId`), поэтому всё, что меняет модель теста, должно сохранять работу лонгрида и результатов по версиям.
- **Отдельный будущий модуль «Опросы»** (как MS Forms и Google Forms: свои анкеты, анонимные ответы, публичные ссылки) делается отдельным планом позже по решению владельца 2026-11-23; в тестах анонимного режима нет.
- **Не входит в этот план:** прокторинг и слежение за браузером, голосовые ответы, платные внешние сервисы проверки.
- Секреты и персональные данные в репозиторий, логи и документы не попадают; все тексты на RU, EN, KK, ZH; слово «эталон» вместо названия стороннего продукта; бюджет CSS расходуется минимально (запас сейчас мал, общие стили папок и таблиц берутся из чек-листов, а не пишутся заново).

## PR 522 — Тест как самостоятельный модуль: данные

**Статус:** план.
**Основание:** разрыв 110, решение владельца 2026-11-22 (вопрос 1): тест самостоятельный модуль, тот же тест входит в курс и в лонгрид.
**Цель:** тест существует сам по себе и подключается куда нужно; правка теста видна во всех местах, где он подключён.
**Зависимости:** нет.

**Заметки по подготовке (по коду):** сейчас `Assessment.courseId` обязателен, `lessonId` необязателен, лонгрид создаёт тесты с `lessonId` в тех же таблицах. От `courseId` зависят: проверка доступности попытки (`ensureAssessmentIsAvailable`), прогресс и результаты курса (`progress.service.ts`), аналитика курсов (`course-analytics`), сертификат (`Certificate.courseId` обязателен). Эти места надо пройти по одному и описать, что они делают для теста без курса. Перед стартом составить таблицу «кто читает `assessment.courseId`» и покрыть её тестами.

| Потребитель | Чтение до PR 522 | Контекст после миграции | Проверяемый сценарий |
| --- | --- | --- | --- |
| Попытки и доступ (`assessment-attempts.service.ts`, course-scope guard) | Курс теста определяет доступ, допуск по завершению курса и курс для уведомлений | Явное размещение определяет курс; прежний вызов выбирает исходное размещение. **Что необходимо сделать:**

- Попытка запоминает, где она пройдена (какое размещение, или самостоятельно); результаты можно смотреть по тесту целиком и по месту.
- Подключение теста в курс, урок и блок лонгрида выбором из списка тестов; отключение не удаляет тест и прошлые попытки.

- Сертификат остаётся за курсом; для самостоятельного теста сертификата нет (вопрос 8).
- Лонгрид продолжает работать как сейчас, его результаты по версиям не меняются.

**Критерии готовности:**

- [ ] отключение не теряет попытки; старые тесты после миграции работают как раньше
- [ ] каждое место, читавшее `courseId`, покрыто тестом; результаты и аналитика курса не меняются
- [ ] интеграционные тесты на Postgres; контракт и документы обновлены

## PR 523 — Самостоятельное использование теста

**Статус:** план.
**Основание:** разрыв 111, решение владельца (вопрос 3): тесты должны быть и самостоятельным инструментом.
**Цель:** тест можно назначить сотрудникам без курса, сотрудник его проходит, администратор видит результаты.
**Зависимости:** PR 522.

**Заметки по подготовке (по коду):** образец — `Assignment` (пользователь, группа, подразделение с потомками, срок, статус); он привязан к `courseId`, поэтому для теста нужна параллельная сущность или общая форма. Список «Мои тесты» у сотрудника уже есть, но показывает тесты через курсы.

**Что необходимо сделать:**
- Назначение теста пользователю, группе или подразделению (с вложенными) со сроком; повторное назначение не дублирует.
- «Мои тесты» у сотрудника показывает и назначенные напрямую, и из курсов, с фильтром и ближайшими сроками.
- Уведомление о назначении и напоминание о сроке (как у курсов).
- Результаты самостоятельного теста видны администратору и руководителю (только своя команда).
- Доступ к самостоятельному тесту по ссылке и QR-коду (по образцу входа по ссылке и QR у чек-листов): ссылку и QR создаёт администратор на странице теста, её можно отозвать и обновить; тест открывается после входа сотрудника (решение владельца 2026-11-22, вопрос 9).

**Критерии готовности:**
- [ ] назначение на человека, группу и подразделение работает, срок виден сотруднику
- [ ] прохождение без курса записывается и не создаёт лишних записей прогресса курса
- [ ] руководитель видит только свою команду
- [ ] ссылка и QR открывают тест, отозванная ссылка не работает, чужая организация не открывается
- [ ] тексты на четырёх языках; e2e: назначить, пройти по ссылке, увидеть результат

## PR 571 — Отчёт по попытке сотрудника (экран и PDF)

**Статус:** план.
**Основание:** разрыв 145.
**Цель:** по любой попытке видно, что ответил сотрудник, что было верно и сколько баллов получено; отчёт сохраняется в PDF.
**Зависимости:** PR 522 (миграция тестов), PR 532, PR 534 (общий механизм PDF), PR 570 (визуальное обновление, см. VISUAL_REFRESH_PLAN.md). Права (решение владельца 2026-11-23): отчёт открывают только администратор организации и создатель курса или теста; руководителю команды и самому сотруднику отчёт не открывается.

**Что необходимо сделать:**
- Страница «Попытка сотрудника»: шапка как в образце (сотрудник, тест, попытка, дата, статус, «верных X из Y», процент, проходной балл, время), под ней вопросы по порядку: текст, тип, максимальный балл, варианты с отметками «верный» и «ответ сотрудника», итог и баллы. Для вопросов на соответствие, порядок и ввод текста показывать правильный и данный ответ рядом.
- Вопросы показываются как их видел сотрудник в этой попытке (снимок попытки, а не текущая версия теста), с отметкой, если тест потом менялся.
- Кнопка «Сохранить в PDF»: печатная вёрстка без меню, номера страниц, дата и название организации в колонтитуле; большие тесты (60+ вопросов) идут фоновой задачей со ссылкой.
- Настройка теста «Оценка вопросов с несколькими ответами»: «всё или ничего» (как сейчас и как в образце) или «частичный балл» (доля верных выбранных минус штраф за лишние, не ниже нуля); применяется к новым попыткам, старые не пересчитываются.
- Ссылка на отчёт по попытке из списка попыток и из аналитики теста (только тем, у кого есть доступ).
- Создатель в данных сейчас не хранится (проверено по базе 2026-11-23: у чек-листов поле автора есть, у тестов и курсов нет; у курса есть только список преподавателей курса). Поэтому в этом PR: добавить тесту поле «создатель», заполнять его при создании, для старых тестов оставить пустым (доступ только у администратора, администратор может назначить создателя); для курса «создателем» считать преподавателей курса из существующего списка, пока у курса не появится поле автора (отдельное решение владельца). Новое поле и перенос данных делаются обратимо.
- Все тексты RU/EN/KK/ZH; в PDF и на экране нет названия стороннего продукта.

**Критерии готовности:**
- [ ] числа в шапке совпадают со списком попыток и аналитикой
- [ ] руководитель не открывает попытку чужой команды, прямая ссылка тоже закрыта
- [ ] вопросы показаны по снимку попытки; изменённый после попытки тест не меняет отчёт
- [ ] PDF на 65 вопросов формируется без обрезанных таблиц; длинные варианты переносятся
- [ ] частичный балл не меняет уже сохранённые результаты
