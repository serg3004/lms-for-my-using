# План развития: Чек-лист — соответствие эталону «Обучение на рабочем месте» (этап 5)

**Основание:** эталонные материалы владельца от 2026-10-28 (PDF «Детальный отчёт по сессии», XLSX «Сводка по сессии», скриншоты формы «5S», редактора шкалы и предпросмотра) и отчёт сверки `REFERENCE_COMPARISON_2026-10-29.md` (оценка соответствия ~58%: отчёты ~40%, функциональность ~85%, настройка ~70%, предпросмотр ~35%), проверенный по `main` после PR 367.
**Статус:** реализованы PR 368–376 (PR 357 вне плана, отложен); остаётся подтверждение владельца по своим эталонным файлам.
**Цель:** это **не новый модуль**. Довести отчёты, настройки листа и предпросмотр до соответствия эталону на 100% по перечню расхождений ниже; соответствие проверяется автоматически (PR 376).

## 0. Границы — обязательно к соблюдению

- Контракты первого плана (разделы 0 и 0.1 `CHECKLIST_WORKPLACE_TRAINING_IMPLEMENTATION_PLAN.md`), планов этапов 2–4 действуют без изменений: никакого нового module boundary, семейство `Checklist*`, `ChecklistSession` — overlay 1:1 над `ChecklistInstance`.
- **Новых пунктов меню нет.** Всё — существующие экраны, диалоги, вкладки и кнопки.
- RBAC не меняется: детальный отчёт, PDF и сводный XLSX видят те, кто видит отчёт сессии (область — `sessionScope()` и таблица прав PR 359). Новых политик нет, кроме явно названных; любое расширение сопровождается cross-tenant тестом.
- Миграции только аддитивные. Уже начатые и завершённые сессии не меняют результат: новые настройки применяются к сессиям, назначенным после сохранения.
- Тексты через i18n, RU/EN/KK/ZH синхронизированы (`locale-sync.spec.ts`, `checklist-module-keys.spec.ts`). Бюджет CSS-бандла почти исчерпан: новый CSS требует осознанного повышения.
- Баллы, проценты и группы считает **один серверный модуль** (`checklist-performance-band.ts` и общий расчёт сессии); клиент и XLSX/PDF не пересчитывают сами.
- Экспорт строится из строк, которые сервер ограничил и записал в аудит (контракт PR 336); CSV-нейтрализация формул сохраняется.
- Перед стартом каждого PR сверять с актуальным `main`. Неподтверждённое помечается `[НЕ ПРОВЕРЕНО]`.

## PR 369 — Оценочные шкалы: редактирование используемой шкалы ✅

**Статус:** реализован (PR 369, #902); визуальные эталоны редактора шкалы перегенерированы.

**Заметки по подготовке:**
- Сейчас `ScaleManagerDialog` делает шкалу только для чтения, если она используется, архивная или системная (`readOnly`). Эталон: используемая шкала редактируется с предупреждением «Обновлённая шкала будет использована для сессий, которые ещё не начаты, для остальных — останется без изменений»; системная («Шкала Да/Нет») показана с замком.

**Цель:** редактирование используемой шкалы работает по правилам эталона и не ломает начатые и завершённые сессии.

**Зависимости:** PR 368.

**Что необходимо сделать:**
- сервер: `PATCH` шкалы разрешён для используемой шкалы (кроме системной и архивной); сессия в статусе «Запланирована» подхватывает текущие уровни при старте (`refreshScaleSnapshot` в переходе `start`), начатые и завершённые читают свой снимок; миграции БД нет;
- пересчёт завершённых результатов не выполняется (контракт PR 362 «Пересчитать» остаётся ручным);
- интерфейс: плашка-предупреждение из эталона в диалоге редактирования используемой шкалы; кнопка «Сделать копию» остаётся для системной и архивной шкал;
- название шкалы: счётчик «N/255» и лимит 255; замок у системной шкалы в списке;
- аудит изменения используемой шкалы (кто, что изменено, сколько листов затронуто).

**Критерии готовности:**
- [x] изменение используемой шкалы не меняет результат начатых и завершённых сессий (DB-integration: до и после);
- [x] не начатая сессия после правки считается по новым уровням;
- [x] системная и архивная шкалы по-прежнему только для чтения;
- [x] права как у строки 2 таблицы (создание и правка шкал), cross-tenant тест;
- [x] RU/EN/KK/ZH; a11y диалога; visual baseline.

**Риски:** гонка «сессия стартует во время правки шкалы»: обновление снимка идёт при старте до первого ответа; снимок читается целиком, поэтому сессия видит либо старые, либо новые уровни, но не смесь.

## PR 369б — Цвета подсветки: настраиваются владельцем ✅

**Статус:** реализован (PR 369б, #903); визуальные эталоны редактора шкалы и диалога настроек перегенерированы.

**Заметки по подготовке:**

**Цель:** администратор (и роли с правом правки шкал и настроек раздела по таблице прав) сам назначает цвета, и отчёт на экране, PDF и предпросмотр используют именно их.

**Зависимости:** PR 369.

**Что необходимо сделать:**
- аддитивное поле `color` у уровня шкалы: свободный выбор цвета (решение владельца 2026-10-29), хранится только как строка `#RRGGBB`, серверная валидация регулярным выражением, никакого произвольного CSS; по умолчанию — по доле баллов уровня: максимум — зелёный, ноль — красный, между — оранжевый;

- сервер хранит выбранные цвета (`color` уровня шкалы, `resultColorLow/Mid/High` настроек) и отдаёт их в `GET /checklist-scales` и `GET /checklists/workplace-settings`; `GET .../report` (PR 370) отдаёт для каждого критерия цвет уровня и для итога и групп цвет диапазона; клиент, PDF и предпросмотр цвет не вычисляют;

- права: цвета уровней — как правка шкал (строка 2 таблицы прав), цвета диапазонов — как настройки раздела (строка 1); аудит изменений.

**Критерии готовности:**

- [x] диапазоны процента настраиваются, пересечения отклоняются (422), дыр нет по построению (границы — пороги);
- [x] значения по умолчанию воспроизводят эталон: полный балл зелёный, неполный оранжевый, ноль красный;

# Решения владельца (блокируют указанные PR)

1. **Китайский язык в PDF (PR 372) — решено 2026-10-29 (принята рекомендация, вопрос снят).** В PDF подключается CJK-шрифт (Noto Sans SC, подмножество под нужные иероглифы или файл шрифта в образе API); для RU/EN/KK используется прежний Noto Sans.
2. **Название «Комментарий» (PR 368).** В эталоне третье поле обратной связи называется «Комментарий», у нас «Следующие шаги» (`nextSteps`). Рекомендую переименовать подпись, ключ данных не менять.
3. **Старый экран «Печать» (PR 372).** Оставить рядом с «Скачать PDF» или убрать. Рекомендую оставить.
4. **Правка используемой шкалы (PR 369).** Правило эталона: обновлённая шкала действует только для ещё не начатых сессий, начатые и завершённые не пересчитываются. Реализовано в PR 369.

5. **Цвета подсветки (PR 369б, 371, 372) — решено 2026-10-29.** Цвета настраивает сам пользователь (цвет уровня шкалы и цвета диапазонов процента); выбор цвета свободный; смена цвета **не перекрашивает** уже завершённые отчёты (цвет хранится в снимке). Значения по умолчанию приняты по рекомендации: полный балл зелёный, неполный оранжевый, ноль красный; дуга красная ниже низкого порога, жёлтая между порогами, зелёная от высокого. Открыто для исправления.
