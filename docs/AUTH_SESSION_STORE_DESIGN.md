# Auth session store design (PR 120)

## Scope

Этот документ фиксирует фактическую реализацию PR 120:

- Prisma-модель `Session`;
- миграция таблицы `sessions`;
- создание сессии при login;
- проверка неистёкшей и неотозванной session со сроком действия;
- тесты создания и истечения сессии;
- staging migration verification.

Полноценный refresh token flow, rotation и endpoint `/auth/refresh` не входят в PR 120. Это отдельная задача PR 137 согласно `docs/DEVELOPMENT_PLAN.md`.

## Модель данных

`Session` хранит только метаданные сессии:

- `id` — первичный UUID;
- `jti` — уникальный идентификатор JWT;
- `userId`;
- `organizationId`;
- `createdAt`;
- `expiresAt`;
- `revokedAt` — признак отзыва.

Индексы созданы для выборок по пользователю и сроку истечения.

## Safe token storage

- База данных не хранит полный JWT.
- База хранит только `jti` и метаданные связи.
- При проверке токена проверяются целостность подписи и соответствие `sub`, `organizationId`, `email` и `jti`.
- Дублирование сессии подавляется уникальным ограничением по `jti`.
- Пользователь и организация проверяются после загрузки сессии.

Такой подход не хранит секретный токен, поэтому отзыв одной сессии не раскрывает другие.

## Жизненный цикл сессии

1. Login проверяет учётные данные пользователя.
2. JWT подписывается со сроком годности и уникальным `jti`.
3. В базе создаётся запись с тем же сроком действия.
4. Каждый защищённый запрос проверяет наличие неотозванной и неистёкшей сессии по `jti`.
5. При logout текущая сессия может быть точно отозвана по `revokedAt`.

## Крайние случаи

- В базе не хранится нехэшированный refresh token.
- Текущий объект `Session` хранит информацию для проверки и отзыва.
- При добавлении refresh flow необходимо хранить в базе только хеш или хэшировать его fingerprint.

## Критерии готовности PR 120

- Prisma-модель `Session` присутствует.
- Миграция `20260606000000_add_sessions` создаёт таблицу `sessions`, индексы и внешние ключи.
- Login создаёт сессию со сроком действия.
- Валидация подписи проверяет отозванные и истекшие сессии.
- Тесты подтверждают создание сессии и отклонение истёкших записей.
- Миграция применена и зафиксирована на staging без pending migrations.
- Существующий поток login не изменён.
