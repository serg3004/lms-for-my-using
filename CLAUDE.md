# Правила работы

---

## 1. Перед каждой задачей

1. `git pull origin main` — получить последние изменения
2. Создать ветку: `git checkout -b claude/название-задачи`
3. Прочитать релевантные файлы — не делать ничего по памяти
4. Найти похожие паттерны в проекте — не изобретать то что уже есть

---

## 2. Поиск лучшего решения

Перед реализацией — обязательно:

1. **Исследовать** — что уже есть в коде по этой теме
2. **Сформулировать минимум 2 варианта** решения
3. **Выбрать лучший** с коротким обоснованием (почему именно этот)
4. **Не усложнять** — простое рабочее решение лучше сложного красивого
5. **Не добавлять лишнего** — только то что явно попросили

---

## 3. Выполнение задачи

- Двигаться маленькими шагами, каждый проверять
- Если что-то непонятно — задать ОДИН уточняющий вопрос, не додумывать
- Не делать ничего сверх задания без явного разрешения
- Проверять что все инструменты доступны перед тем как обещать результат

---

## 4. Определение «готово»

Задача считается выполненной только если:

- [ ] Код написан и соответствует задаче
- [ ] Тесты запущены и проходят (`pnpm test` или соответствующая команда)
- [ ] TypeScript компилируется без ошибок (`pnpm typecheck`)
- [ ] Lint чистый (`pnpm lint`)
- [ ] `git status` чистый (всё закоммичено)
- [ ] `git log origin/ветка --oneline` подтверждает что коммит на GitHub
- [ ] Пользователь уведомлён: «запушено в ветку X — нужно создать PR на GitHub»

---

## 5. После выполнения задачи

1. `git add <конкретные файлы>` — никогда не `git add .` без проверки
2. `git commit` — понятное сообщение: что и зачем изменено
3. `git push origin claude/название-задачи`
4. Сообщить пользователю: название ветки, что сделано, что нужно сделать вручную (создать PR)

---

## 6. Запрещено (никогда, без исключений)

- Коммитить напрямую в `main`
- Делать `git push --force`
- Говорить «отправлено на GitHub» — только «запушено в ветку X»
- Говорить «готово» без запуска тестов
- Создавать ветки или делать коммиты без явного задания от пользователя
- Добавлять код/функции которые не были запрошены
- Делать предположения вместо того чтобы прочитать реальный файл
- Использовать `gh` без проверки что он установлен (`where gh`)

---

## 7. Автономная работа

При работе без постоянного контроля:

- Каждый шаг логировать в ответе (что сделал, что проверил, результат)
- При любой неожиданной ошибке — остановиться и сообщить, не пытаться "починить вокруг"
- Если задача оказалась сложнее чем ожидалось — сообщить до того как потратить много времени
- Придерживаться минимального изменения: решать только то что сломано, не рефакторить вокруг

---

## 8. Технический стек (справка)

- **Монорепо:** Turborepo + pnpm
- **API:** NestJS + Prisma + PostgreSQL (`apps/api`)
- **Web:** React 19 + Vite + TypeScript (`apps/web`)
- **Деплой:** Railway (web nginx, api NestJS, PostgreSQL)
- **Тесты API:** Jest (`pnpm --filter api test`)
- **Тесты Web:** Vitest (`pnpm --filter web test`)
- **Typecheck:** `pnpm typecheck`
- **Lint:** `pnpm lint`
